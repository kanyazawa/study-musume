# Study Musume アマガミ方針設計

## Summary

- `study-musume` は今後、`対戦中心の学習ゲーム` ではなく `日常と関係構築を主軸にした学習恋愛シミュレーション` として再定義する。
- プレイヤー体験の中心は `勉強を続けるとキャラとの距離が少しずつ縮まること` に置く。
- 学習は報酬獲得のための作業ではなく、`会話 / 約束 / 個別イベント / ルート分岐` を進めるための生活行動として扱う。
- 目標は `勝つこと` より `誰とどう時間を過ごすかを選び、その結果として関係が変わること` にする。

## Design Pillars

### 1. 日常の積み重ねを主役にする

- 派手な一発イベントより、短い会話や毎日の選択の積み重ねで空気が変わる設計にする。
- キャラとの距離は `好感度の数値上昇` だけでなく、`会話内容`, `呼び方`, `反応`, `選べる行動` の変化で感じさせる。

### 2. ヒロイン別ルートを明確にする

- 全員と薄く仲良くなるゲームではなく、途中から `誰を本命として追うか` をはっきり選ぶ構造にする。
- ルートに入った後は、そのキャラ専用の出来事が増え、他キャラは自然に距離が出る。

### 3. スケジュール選択に意味を持たせる

- `何を勉強するか` と同じくらい `いつ誰に会うか` を重要な選択にする。
- 日付、時間帯、場所、約束の有無で発生イベントが変わるようにする。

### 4. ご褒美は露出ではなく親密さにする

- 報酬の中心は `イベント解放`, `特別会話`, `思い出`, `呼び方変化`, `ボイス`, `表情差分` に置く。
- セクシーさより `この子が自分をちゃんと見てくれている感覚` を価値にする。

### 5. 周回したくなる構造を持たせる

- 1周で全部回収する設計にしない。
- 別キャラ、別の選択、別の日付条件で異なる空気になるようにする。

## Player Fantasy

- 勉強を頑張るほど、ただ成績が上がるだけでなく、誰かとの関係が具体的に進む。
- 毎日の放課後に `今日は誰とどこで過ごすか` を選ぶこと自体が楽しい。
- 特別なイベントは突然開くのではなく、過去の積み重ねが効いて開く。
- ルートに入ったキャラとの距離感が、他キャラとは明確に違って見える。

## Core Loop

1. 朝または登校時に、その日の予定と気になるイベントを確認する。
2. 授業や勉強で学習進行を進める。
3. 放課後に `会う / 勉強する / 約束を消化する / 別の用事を優先する` を選ぶ。
4. 会話、ミニイベント、個別イベントで関係値とフラグが変化する。
5. 夜にその日の振り返りが入り、次の日に向けた示唆が出る。
6. 一定条件で `ルート確定`, `中盤イベント`, `終盤イベント`, `エンディング` に進む。

## Day Structure

### 1日の基本フェーズ

- `朝`
  - 日付確認
  - 予定確認
  - 約束イベントの警告
  - その日の注目キャラ表示
- `昼`
  - 勉強進行
  - 学力上昇
  - 該当キャラとの軽い会話
- `放課後`
  - メイン選択フェーズ
  - 場所移動
  - キャラ接触
  - 個別イベント発火
- `夜`
  - 振り返り
  - 好感度やフラグ整理
  - 明日の示唆

### 日次設計のルール

- 1日に何でもできる構造にはしない。
- `誰かと会う` ことには機会コストを持たせる。
- 約束を破る、別の行動を優先する、必要勉強量を満たせない、といった損失も物語上の意味を持たせる。

## Route Structure

### 全体構成

- `共通序盤`
  - 全キャラと接点を作る期間。
  - 勉強、雑談、軽イベントで好みのキャラを見つける。
- `個別ルート確定前`
  - 特定キャラに寄せた行動を取ると、専用イベントが増え始める。
  - 他キャラと均等に接しているだけでは深いイベントには入らない。
- `個別ルート確定`
  - 一定日付までに条件を満たすとルート固定。
  - この時点で専用会話、専用分岐、専用終盤イベントを解放する。
- `終盤`
  - 関係の深まりだけでなく、キャラ固有の悩みや目標を一緒に越える段階。
- `エンディング`
  - 勉強結果と関係結果の両方を反映した結末にする。

### ルート確定条件の基本

- 好感度だけで決めない。
- `日付条件 + 好感度 + 行動回数 + 特定イベント既読 + 勉強状況` の組み合わせで判定する。

例:

- `好感度 Lv4 以上`
- `study` 系交流を 4 回以上
- `chat` 系交流を 3 回以上
- `特定の放課後イベント読了`
- `中間テスト準備イベントを未失敗`

## Character Event Policy

### イベントの粒度

- `ひとこと`
  - 数秒で終わる短い反応
- `ミニイベント`
  - 5から10行程度の会話
- `個別イベント`
  - ルート進行に関わる主要イベント
- `約束イベント`
  - 指定日や指定時間にしか発生しない強いイベント
- `終盤イベント`
  - エンディング分岐に影響する決定的イベント

### イベント設計の基本

- どのイベントも `関係が1段階進んだ実感` を残す。
- イベントの価値は報酬量ではなく `空気が変わること` に置く。
- 勉強行動はイベント解放条件として自然に織り込む。

例:

- 一緒にテスト対策した
- 苦手分野を教わった
- 休み時間に前回の会話を覚えていた
- 約束した日に来るかどうかで印象が変わる

## Study Musume への落とし込み

### 学習の役割

- 学習はゲーム外の義務ではなく、キャラとの接点を生む `生活行動` として扱う。
- `授業`, `読解`, `英作文`, `復習` はそれぞれ交流の文脈を持てるようにする。

例:

- `授業`: 一緒に進める基本導線
- `復習`: 支えてもらう、努力を見てもらう導線
- `英作文`: 価値観や考え方が見える導線
- `読解`: キャラの反応やコメントを差し込みやすい導線

### 対戦機能の扱い

- `MultiplayerMatch` を作品の中心には置かない。
- 残す場合は `実力確認`, `試験前の腕試し`, `ライバル要素` として脇役化する。
- 主導線は `勉強 -> 放課後交流 -> イベント` に移す。

### ホーム画面の役割

- ただのハブではなく `今日誰に会えそうか`, `今日の約束`, `ルート進行上の重要日` が見える画面にする。
- 最優先情報は `ランキング` ではなく `日付`, `時間帯`, `注目イベント`, `次の約束` にする。

## Required State Design

### 既存値で活かせるもの

- `stats.affection`
  - 好感度の基礎値として継続利用
- `stats.relationshipTotals`
  - `talk`, `chat`, `study`, `gift` の累積条件に使える
- `stats.relationshipEvents`
  - イベント解放済み / 既読管理として継続利用
- `stats.relationshipMoments`
  - 最近の空気感ログとして活かせる
- `stats.examDate`
  - 学習と物語の締切日として活用できる

### 新規で必要になる値

- `stats.calendarState`
  - 現在の日付、曜日、季節、周回番号
- `stats.timeSlot`
  - `morning`, `day`, `afterSchool`, `night`
- `stats.routeState`
  - `common`, `pending`, `locked`, `ending`
- `stats.routeCharacterId`
  - 現在の本命ルート対象
- `stats.promiseState`
  - 約束した日付、相手、場所、達成状態
- `stats.storyFlags`
  - 会話や条件達成の細かい分岐管理
- `stats.studyProfile`
  - 文法、単語、読解、英作などの学習傾向

### 日次管理の方針

- 現在の `dailyLoopState` は短期的には残す。
- 中期的には `今日の3フェーズ達成管理` から `日付と時間帯ベースの生活管理` へ移行する。
- 当面は `dailyLoopState` を `学習進行の最低保証` として使い、物語進行は別の `calendarState` で持つ。

## Content Rules

- 台詞は `安心感`, `特別感`, `少しの照れ` を軸にする。
- あからさまな誘惑より、`前の会話を覚えている`, `一緒に頑張った時間が残っている` ことを重視する。
- 好感度が上がるほど、反応の温度と踏み込み方が変わるようにする。
- 個別ルートに入る前から、キャラごとに `会話テンポ`, `距離の詰まり方`, `感情の見せ方` を差別化する。

## MVP Scope

### Phase 1

- ホームに日付と注目イベント枠を追加
- キャラ交流を `放課後に会う` という形で明示化
- 既存 `relationshipEvents` を `共通序盤イベント` として再整理
- `おすすめ行動` を `誰に会うか` 優先に寄せる

### Phase 2

- `約束イベント` の導入
- 日付条件付きイベント解放
- ルート候補状態の導入
- キャラごとの会話差分拡充

### Phase 3

- 個別ルート確定
- 終盤イベントとエンディング分岐
- 周回時の既読管理とショートカット整備

## Implementation Order

1. `routeState`, `calendarState`, `promiseState` の保存設計を追加する。
2. ホーム画面を `今日の生活画面` として再設計する。
3. `relationshipEvents` の定義形式を `日付`, `場所`, `時間帯`, `前提フラグ` 対応に広げる。
4. `CharacterInteraction` と `RelationshipEventReader` を、ルート進行画面として強化する。
5. `gameLoopUtils` のおすすめ行動ロジックを `学習優先` と `関係進行優先` の両立型にする。
6. 最後に `MultiplayerMatch` など既存の強いゲーム的要素を脇役へ再配置する。

## Non-Goals

- 最初から全キャラ全ルートを完成させることは目指さない。
- 戦闘やランキングを完全に削除することも目指さない。
- いきなりフルADV化して大規模なシナリオエンジンを新設することも目指さない。

## Decision

- `study-musume` の主ジャンルは、今後 `学習ゲーム` 単体ではなく `学習恋愛シミュレーション` として扱う。
- コア体験は `勉強で強くなること` ではなく `勉強を通じて誰かとの日常が変わっていくこと` に置く。
- 実装は既存の `affection`, `relationship`, `dailyLoop` 基盤を土台にしつつ、`日付`, `時間帯`, `個別ルート` を追加して拡張していく。
