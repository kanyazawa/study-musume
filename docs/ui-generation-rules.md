# UI Generation Rules

`study-musume` で UI を生成するときの共通ルールです。

## 方針

- まずは **配置だけ** を決める
- ボタンやカードの見た目は **あとで AI で別生成** する
- 最初の出力は **ワイヤーフレーム寄り** にする
- できるだけ **1ファイル完結** にする
- 画面全体の **情報量を減らす**
- 文字で説明しすぎず、**直感で理解できる配置** を優先する
- 迷ったら **説明を足すより削る**

## 固定する世界観

特別な指定がない限り、新しい画面は次の前提で作る。

- 背景は学校の教室
- 画面上部にキャラの顔か上半身が見える
- 下半分から下部に主要 UI を集める
- スマホ縦画面を優先する
- ソシャゲ風の情報整理にする

## スマホ向け構図ルール

- 画面構図は基本的に `背景 -> キャラ -> セリフ -> 下部操作シート` の順で考える
- 上部だけでなく、画面全体で情報を詰め込みすぎない
- フッターやタブや見た目のまとまりで分かる情報は、タイトルや補助ラベルとして重ねて出さない
- 戻る導線がフッターなどにあるなら、上部の戻るボタンは基本的に置かない
- 白いモヤ、白ベール、強い白かぶせは勝手に足さない
- セリフは横長よりも、やや細めで縦に伸びる形を優先してよい
- キャラは背景の上、セリフの下にいる見え方を優先する
- キャラの顔まわりは基本的に **UI を重ねないセーフゾーン** として扱う
- まずはキャラを動かすより、吹き出しや上部UIを顔から逃がす
- 帽子や髪飾りなど、画面内に見えているのに不自然に切れて見える配置は避ける
- 画面全体はなるべく固定しつつ、必要なスクロールは下部ワークスペース内だけで完結させる
- 説明文、補足文、状況文を何段も積まない
- 1つの意味に対して、見出し・小見出し・説明文を全部は置かない
- まずは「短いラベル1つ」か「見た目だけで分かるUI」を優先する

## 生成の2段階

### 1. 配置を決める段階

- 背景、キャラ枠、タイトル、タブ、リスト、下部ボタンの位置だけ作る
- ボタンやカードはただの箱でよい
- 色や装飾は最小限でよい
- アニメーションは不要
- 余計なコンポーネント分割はしない
- 説明文や補助テキストは最初から盛り込まない

### 2. 見た目を足す段階

- ボタン
- カード
- バッジ
- 装飾ライン
- 発光やグラデーション

この段階だけ AI で追加生成してよい。

## 必須レイアウト

新規ページでは、まずこの順で枠を置く。

1. 背景の教室エリア
2. 上部キャラ表示エリア
3. ページタイトル or 状態表示エリア
4. タブ / フィルター / 切り替えエリア
5. メインコンテンツエリア
6. 下部操作ボタンエリア

## repo内の実装ルール

- 最初は `single-file` の JSX でよい
- 試作ページは `src/pages/*PageV0.jsx` に寄せる
- 迷ったら `src/pages/_PageV0Template.jsx` を起点にする
- React + Vite 前提で書く
- Next.js 前提のコードは持ち込まない
- shadcn/ui 前提の分割構成は持ち込まない

## Live2D とキャラ位置の調整ルール

- 配置調整では、まずレイアウト全体を動かさずキャラだけを動かす
- ただし顔との衝突は、キャラ位置変更より先に **UI の退避** で解決する
- 微調整は `少し右` `下に強め` `右:下=1:3` のような指示をそのまま最小差分で反映する
- 一度に大きく組み替えず、1軸か1比率ずつ直す
- Live2D が動かないときは CSS だけでなく、`src/components/character/Live2DViewer.jsx` と `src/utils/live2dModelRegistry.js` も確認する
- `Live2DViewer.jsx` の transform 固定や、`live2dModelRegistry.js` の `stage` / `stageOverrides` が見た目の位置を止めていることがある
- 静止画フォールバックを使う画面では、Live2D と同じ方向に位置を合わせる
- 今後のシーンページでは、顔の近くに上部UIを置く場合は **face safe zone** を前提にして構図を決める

## v0 に渡す定番の言い方

```txt
[画面名] のUIを作ってください。

重要:
- 新しいプロジェクト一式は作らないでください
- ファイル分割はしないでください
- 1ファイルだけで出してください
- React/Vite に貼りやすい最小構成にしてください

今回ほしいのは完成デザインではなく配置案です。
ボタンやカードの見た目は後でAIで別生成する前提なので、今回は作り込まないでください。

レイアウト条件:
- スマホ縦画面
- 背景は学校の教室
- 画面上部にキャラの顔か上半身が見える
- 下部にソシャゲ風の操作UIをまとめる
- 画面全体の情報量は少なめにする
- セリフはやや縦長でよい
- タイトル、タブ、メイン一覧、下部ボタンの枠を置く

不要:
- components / hooks / lib / styles への分割
- 外部ライブラリ
- 状態管理
- アニメーション
- アイコンの作り込み
- 長い説明
- 補助ラベルの多用
- 説明文の重ね置き

出力:
- 単一ファイル
- コピペしやすい形
- ワイヤーフレーム寄り
- 見た目より配置を優先
```

## 補足

- 細かいボタン演出は後段で足す
- 最初の段階では「情報の位置」と「操作の流れ」が正しければ十分
- 「読めば分かるUI」より「見れば分かるUI」を優先する
